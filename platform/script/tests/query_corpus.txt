# The VM query API fixture corpus — ADR 0001 §4, App Flow #9.
#
# One entry per line: <name> <TAB> <runner> <TAB> <key,key,key> <TAB> <total>
# The name is what `module_object` answers to; the keys are what `object_keys`
# must answer for it, sorted, each name once; the total is the object's full
# entry count, named or not. A module this VM does not install is drift, and so
# is a key set that moved.
#
# The total matters because a name is not always recoverable: a key registered
# in Rust with `id!` and never spelled by any source is an id the VM cannot
# turn back into a string — the same gap its own "Did you mean" lists have —
# and `object_keys` does not invent one. Recording the total keeps such an
# entry visible: a key the corpus cannot name is still a diff.
#
# The runner names the crate whose test checks the entry, because the modules a
# real isolate installs span three crates and no single `cargo test` builds
# them all:
#
#   script   — installed by makepad-script itself (a bare `ScriptVmBase`).
#              Checked by `cargo test -p makepad-script`
#              (platform/script/tests/query_api_corpus.rs).
#   widgets  — installed by a Splash isolate's widget-facing setup (the widget
#              registry, the host and storage modules, the sys module, and the
#              Cx-free runtime's net). Checked by
#              `cargo test -p makepad-widgets`
#              (widgets/tests/vm_query_corpus.rs), which reads this same file.
#
# The corpus is the review artifact for the query API's stability promise: the
# fork has no CI and makepad-script is not on crates.io, so a change to either
# function — or to a module's members — shows up here as a diff a person names
# in the pull request. Regenerate with QUERY_CORPUS_WRITE=1, then read the diff.
